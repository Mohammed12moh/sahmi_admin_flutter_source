# Sahmi Admin

لوحة Flutter منفصلة لإدارة Sahmi، تستخدم نفس مشروع Supabase. الواجهة عربية RTL وثيم داكن.

## التشغيل

1. ثبّت Flutter 3.24 أو أحدث.
2. راجع `supabase/admin_schema.sql` وقارنه بجداول مشروع Sahmi الحالية قبل تطبيقه في Supabase SQL Editor.
3. أنشئ مستخدم المشرف من Supabase Auth.
4. بعد التأكد من UUID الصحيح، نفّذ إدخال Super Admin المعلّق في نهاية ملف SQL مع استبدال UUID والبريد.
5. لا تمنح أي مستخدم دوراً من خلال Flutter؛ إدارة الأدوار تحتاج دوال خادمية موثوقة وتدقيقاً.
6. شغّل:

```bash
flutter pub get
flutter run --dart-define=SUPABASE_ANON_KEY=YOUR_SUPABASE_ANON_KEY
```

رابط Supabase مضبوط افتراضياً في `lib/main.dart`. المفتاح المستخدم يجب أن يكون anon/publishable فقط، وليس service-role.

## الوضع الحالي وحدوده

- تسجيل الدخول بالبريد وكلمة المرور عبر Supabase Auth.
- أساس لوحة التحكم وإحصاءات العدّ، قوائم قراءة عامة، شاشة إدخال إشعار إلى queue، وشاشة إعدادات أولية.
- صلاحيات البيانات تعتمد على RLS في قاعدة البيانات، وليس على إخفاء عناصر الواجهة.
- أسماء الجداول في لوحة التحكم (`profiles`, `deposit_requests`, `withdraw_requests`, `market_signals`) افتراضات؛ طابقها مع مخطط تطبيقك الحالي.
- لا توجد في هذه النسخة إجراءات مالية للموافقة على الإيداعات/السحب أو تعديل الرصيد؛ هذه تحتاج معرفة مخطط الحسابات الحالي وتنفيذ معاملات ذرّية ودوال RPC خادمية لمنع تكرار الصرف.
- Realtime وإرسال FCM الفعلي يحتاجان تحديد الجداول/الأحداث الموجودة وإنشاء Edge Function آمنة.
- MFA يمكن تفعيله من Supabase Auth؛ شاشة الدخول تعرض تنبيهاً، لكن تدفق تحدي MFA يحتاج استكماله حسب إعدادات مشروعك.
- لا تضع مفاتيح FCM أو Supabase service-role داخل تطبيق Flutter.

## ملاحظات أمنية

هذا مشروع أساس قابل للتطوير وليس منتجاً إنتاجياً مكتملاً. اختبره في بيئة تجريبية، راجع سياسات RLS لكل جدول موجود، ولا تطبق تغييرات مالية قبل مراجعة قاعدة البيانات الحالية.
